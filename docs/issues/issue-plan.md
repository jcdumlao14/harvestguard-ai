# Public GitHub Issues Plan

Create these Issues after the repository is published. Each Issue should
include the relevant acceptance criteria, a definition of done, dependencies,
and evidence required for closure.

## Milestone 1 — Specification and foundation
- HG-PLAN-01: Review product specification and acceptance criteria.
- HG-PLAN-02: Publish architecture, AGENTS.md, and agent-team process.
- HG-PLAN-03: Create GitHub Projects board or public task tracker.

## Milestone 2 — Core application
- HG-APP-01: Implement database schema and migrations.
- HG-APP-02: Implement inventory API and persistence.
- HG-APP-03: Implement stock movement and waste records.
- HG-APP-04: Implement dashboard calculations and UI.
- HG-APP-05: Add API and frontend tests.

## Milestone 3 — Delivery
- HG-REL-01: Add Docker Compose and clean-start validation.
- HG-REL-02: Add pull-request CI.
- HG-REL-03: Deploy a public demonstration.
- HG-REL-04: Add controlled production promotion and rollback drill.

## Milestone 4 — Reliability
- HG-OBS-01: Add trace-correlated logs, metrics, and traces.
- HG-OBS-02: Build the observability dashboard.
- HG-OBS-03: Add and trigger a user-impact alert.
- HG-OBS-04: Implement responder policies and audit records.
- HG-OBS-05: Demonstrate recovery and escalation.

## Evidence
Use actual GitHub Issue and pull-request URLs after they exist. Keep the
tracker public if required by the course. Do not fabricate links or agent usage.
